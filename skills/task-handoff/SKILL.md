# 任务交接

创建一份不依赖聊天历史的可执行交接文件。

## 触发条件

- 仅在 `$task-handoff` 或用户明确要求交接、接力、续接上下文、上下文总结、换一个 AI 继续时手动触发；未明确要求时不自动运行。
- 当可靠的运行时指标报告上下文不足或出现压缩警告时，提示用户可手动触发本 Skill，但不自动运行；没有百分比时绝不凭空编一个。
- 先安全结束一个进行中的工具调用，并捕获它的结果和会话 ID。
- 普通扫描（新任务/任务切换/上下文压缩时的文件名、标题、YAML frontmatter 低 token 发现）不是触发本 Skill 的条件。

## 交接文档发现与元信息

- 元信息完整性：交接文档 YAML frontmatter 须包含 type、status、创建时间、最后更新、项目（项目路径，如 `/absolute/project/path`）、任务、关键词、摘要、适用场景、工作区、分支、PR（完整 URL，如 `https://github.com/OWNER/REPO/pull/123`）、关联文件、关联 ID；标题在 YAML 缺失时作备用命中。
- 字段规范：项目字段使用可定位的项目路径，PR 字段必须为完整 URL（`https://github.com/.../pull/...`），不能只写 `#9`。
- 读取正文条件：仅在用户手动触发本 Skill 后，且命中强关联或多个弱关联时，才按需读取相关正文；命中仅提示可能相关，不自动读正文。
- 扫描与触发分离：新任务/任务切换/上下文压缩时的低 token 扫描（只读文件名、标题、YAML frontmatter）不触发本 Skill。

## 收集事实基线

优先使用当前允许的证据，而不是记忆：

1. 目标、范围、决策和批准。
2. 工作区、分支、基线、提交、脏文件、PR 和未推送的工作。
3. 已改动的文件和行为变化。
4. 实际运行过的测试、构建、探针、日志和检查，附确切结果。
5. 本地/开发/预发布/生产状态、部署、配置和在线会话。
6. 失败、原因和可行替代方案。
7. 剩余工作、阻塞项、所有者决策和第一个安全动作。

把计划内的工作、本地代码、提交、远程分支、PR、部署和人工验证分开。

## 保护状态与机密

- 交接只授权检查和写入它的文件。不要 commit、push、部署、重启、重跑付费任务或变更外部状态。
- 遵循项目规则；绝不读取禁止的文件。
- 绝不记录机密或敏感负载。只记录凭据的存在及其授权的取用位置。
- 列出后继者不得覆盖的用户自有文件或资源。

## 保存交接文件

使用本地时间。目录和文件名必须分开构造：

```text
目录：~/Documents/AI任务交接/YYYY/MM/
文件：DD-项目-任务.md
```

例如 2026 年 8 月 18 日的正确路径：

```text
~/Documents/AI任务交接/2026/08/18-示例项目-任务.md
```

禁止重复日期：

```text
~/Documents/AI任务交接/2026/08/2026-08-18-示例项目-任务.md
```

规则：

- `项目` 从产品/仓库推导，`任务` 从具体目标推导。
- 文件名前缀 `DD` 只写两位日期，不再包含年份和月份。
- 把空白和文件系统保留字符替换为 `-`；合并连续连字符。
- 对同一天、同一项目、同一任务，更新原文件。保留 `创建时间`；更新 `最后更新`。
- 如果匹配到的是不同任务，就起一个更具体的名字，而不是覆盖它。
- 缺年份和月份目录时创建它们。不要删除更早的交接文件。
- `assets/handoff-template.md` 是唯一输出模板：必须保留 YAML frontmatter、标题和章节顺序，不得自由改成交接摘要。
- 只有 `关键决策`、`踩坑与无效尝试`、`待用户或外部负责人确认` 三个章节可在确实为空时删除；其余章节必须保留并填写事实。

如果写入失败，把完整交接内容连同预期路径和错误一起返回在聊天里。

## 质量门

保存前验证：

- 下一个 AI 能找出第一条命令或第一次检查。
- 每一条状态主张都有证据，或标记为未验证。
- 失败的尝试及其原因被保留。
- 必需的批准和禁止的动作是明确的。
- 重要的路径、ID、URL、命令和会话 ID 都包含在内。
- 不含机密或无关的聊天叙述。

回复时按仓库根 `AGENTS.md` 的本地路径汇报规则执行，并给出当前状态和唯一下一步动作。在上下文极低时，保存并提问后停止新工作。
