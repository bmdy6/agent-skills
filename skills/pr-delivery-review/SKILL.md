# PR 交付审查

本技能充当最终交付闸门，而不是主开发流程。`project-director` 应在实现阶段就防止这些问题；本技能负责抓住发布或合并之前仍残留的问题。

先从只读检查开始。本技能本身不授权编辑、commit、push、开 PR、回复、合并、部署或外部状态变更。当前用户请求可能另行授权本地修复或后续交付操作。

## 1. 建立事实基线

- 阅读全局代码规范、仓库说明、当前 PR 指南，以及这些说明所要求的任务文档。
- 根据当前证据重建已接受的需求、非目标、已知限制和验收标准。不要只凭 diff 推测。
- 检查分支与基线、工作树、已暂存与未暂存的 diff、未跟踪文件、最终 diff、提交列表、现有 PR 描述、review 和检查。保留用户自有的改动。

## 2. 复核行为与影响

- 为已改动和明确不受影响的情况建立条件矩阵。验证最终的下游或用户可见结果，而不仅仅是修改过的函数。
- 通过调用方和消费方追踪已改动的字段、枚举、schema、返回值、错误、配置、提示词和共享辅助函数。检查兼容性和现有项目机制。
- 对于数据库、缓存、追踪、消息、文件和外部调用，验证在成功、校验失败、异常、提前返回、超时或取消、重试耗尽、回退和清理等各种情况下的位置与行为。
- 检查归属、幂等性、重复副作用、负载大小、敏感数据、资源生命周期，以及可观测性或清理失败是否会影响业务路径。

在相关时应用针对性风险检查：

- AI 输出：provider 响应结构、语义完整性、合法未改动输出、重试、回退和缓存污染。
- 追踪与日志：正确的错误阶段和分支、正常路径无 ERROR、上下文量有界、真实系统回读。
- 规则与动作：跨子类型的真值表，以及过滤或推送等最终下游动作。
- 配置与状态：合并优先级、修正、去重、唯一性、幂等性，以及跨条目一致性。
- 配置：来源优先级、密钥边界、启动与关闭、回退、热重载、部署同步和回滚。

针对提示词 / Skill / 规范 PR（仅此类，不泛化到普通代码 PR）：CI 绿、格式校验、模型审查为必要但不充分证据。人工语义审查必须检查前后行为、用户可见副作用、权限扩大/收紧、删除/清理边界与相关 Skill/私有规则冲突，并用至少一个实际反例验证（例如把新增/修改的必须/允许/禁止/清理/权限规则逐条代入反例输入，观察前后行为差异），反例写入审查结论。

- 外部模型审查超时不等于通过或失败；先确认没有遗留进程，不无限重复同一请求，再用当前 diff、CI 和已有审查做有界替代复核，并在 PR 中明确未完成的审查项。

## 3. 评估证据

- 将每一条实质性需求和失败路径映射到证据上。测试套件通过只能证明它所覆盖的部分。
- 运行仓库规定的检查和针对性测试。当需求涉及外部服务、持久化状态、运行时生命周期或用户可见流程时，使用集成或真实系统回读。
- 把目标代码的失败与无关的环境噪声区分开。说明每一项未运行或不可用的检查。
- 审查提交演变。区分计划内的增量与修正性提交；反复修复抽象、归属、所有权、生命周期或范围的问题，需要重新做一次整体方案审查。
- 标记无关改动、临时工作、先加后删的历史、过期文档、配置漂移，以及与最终 diff 不再匹配的 PR 描述。

被授权时，使用 `handling-code-review` 做与风险成比例的独立审查。必须对照当前代码验证发现；不要盲目接受自动化或人工 review 的结论。

## 4. 报告并解决发现

- 在编辑之前报告发现，按严重程度排序，并关联到需求、代码路径、影响和缺失的证据。
- 如果用户只要求审查或报告，在给出发现后停下，仅当需要做出决策时才询问方向。
- 如果用户已要求修复，或要求在解决问题后继续交付，则一次一个地用最小正确改动实现已授权的修复。在受影响的路径上测试每个修复。
- 如果修复改变了抽象、所有权边界、兼容性契约、错误归属、运行时生命周期或已接受的范围，重建相关的条件和路径矩阵，而不是再叠一个窄补丁。
- 修复后，针对最终 diff 和提交历史重新运行适用的仓库检查、针对性测试、真实系统验证以及本次交付审查。持续到阻塞项清除，或出现真正需要用户决策的点。
- 绝不要把修代码的授权当作 commit、push、PR 回复、合并、部署或公司状态变更的授权。

## 5. 给出一个结论

- **不可提交：** 需求、范围、实现、兼容性、安全性或必需证据存在阻塞性缺口。
- **仅可开草稿 PR：** 实现可以审查，但仍需实质性的环境、集成、外部系统或人工验证。
- **可提交审查或合并：** 需求、受影响路径、仓库检查和必需的真实证据都完备；残留风险单独列出。

先按严重程度列出发现，然后是结论、已核实的证据、缺失的证据，以及确切的下一步动作。不要把阻塞项藏进摘要里。

只有在得出结论且用户另行授权后，发布流程阶段才可 commit、push 或开 PR。使用仓库自己的命令和 GitHub 发布技能来做传输；不要在这里重复实现。
