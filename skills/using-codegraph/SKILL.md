## 目标

用最少的搜索先把工作集缩小，再在确实需要结构关系时调用 CodeGraph；不要为了“熟悉项目”从全仓反复 grep/read，也不要小任务强制建图。

## 分层定位

1. **先看项目入口**：进入陌生仓库先读根 `AGENTS.md`；若已有 repo-map/项目说明，只读与当前任务有关的代码导航、入口和验证信息，不把整份项目说明常驻加载。
2. **能精确找就直接找**：已知字符串、文件名、符号或单文件改动，优先 `rg` / 精确 `read`；找到 1～3 个候选文件后就停，不再为“更保险”扩大搜索。
3. **概念定位先收窄**：只知道“某功能在哪里”时，先用 repo-map 的“概念→区域 / 任务→落点”缩小目录；地图只给到目录时先在该目录内 `rg`，定位到具体文件后才 `read`。没有 repo-map 才做最小目录扫描。
4. **跨文件关系才用 CodeGraph**：调用链、事件流、跨模块影响、重构影响面、受影响测试等结构问题，确认仓库可信后使用 `codegraph explore` / `callers` / `impact` / `affected`。
5. **图谱只负责导航**：CodeGraph 返回的是候选关系；编辑前必须精确阅读相关源码，否定性结论也要用 `rg` / 类型检查 / 测试核实。

## CodeGraph 操作

- 有 `.codegraph/codegraph.db`：先 `codegraph status`；提示过期再 `codegraph sync`。
- 没有索引：只有任务确实需要跨文件结构关系时才 `codegraph init`；小改动、纯文档、非代码任务不初始化。
- 初始化前把 `.codegraph/` 加入 `.git/info/exclude`，绝不提交索引数据库。
- 改动后仍跑仓库正常的测试、lint、类型检查和构建；图谱不能替代验证。

## 停止条件

- 已经定位到少量候选文件且源码能回答问题：停止继续搜索，进入阅读/修改/验证。
- 两种合理定位方式仍不收敛：不要继续全仓循环搜索，汇报已知/未知并换成结构性查询或请求一个关键澄清。

## 验证

1. `codegraph status`（若使用）报告索引健康，`git status --short` 不显示 `.codegraph/`。
2. 小改动可以完全不调用 CodeGraph；跨文件任务能用图谱把目标缩到少量关键文件。
3. 最终结论由源码/测试支撑，而不是只引用图谱结果。
