# 学习知识库工作流

先判断用户是在：先存素材、批次整理、提炼待学问题、接受训练、整理调研、沉淀正式知识，还是维护知识库。只加载当前路线需要的参考；目录与命名以知识库当前 AGENTS.md 和实际文件为准，不恢复旧库的平行草稿、生成阅读层或概念卡体系。

## 真源与边界

- **唯一真源**：knowledge-mcp。日常使用其 search / read / show_diff / apply_change / create_document / move_document / validate 等受保护能力。
- **Workbench**：只读派生层。只有长期入口和带 阅读/沉淀 tag 的成品文章会发布；绝不直接写 Workbench 正文。
- **个人调研**：按知识库当前规则维护既有调研文章和辅助材料；长期结论最终回到对应主文章，不按旧路径新建目录。
- **一主题一篇**：写入前先 search；已有主题就补原文，确实是独立长期主题才新建。

## 路由

### 先收集，之后由 AI 整理

收集适用于“先存着”“放草稿箱”“收藏这个”，也包括用户已授权的主动暂存：对话里出现以后值得继续看的个人问题、资料或想法时，无需逐条确认。普通闲聊、重复内容和公司资料不自动存入个人草稿；用户明确说不记时不写。“整理这批知识”表示处理已有收集项。

1. 读取知识库当前 AGENTS.md，搜索并读取已有的「知识待整理」入口；命名或路径有出入时核对实际文件，不另建收件箱。
2. 明确要求保存或符合已授权的主动暂存条件时，先查重，再通过受保护写入暂存素材，保留日期、来源、原意和用户已经说出的想法，标明待整理/待学习。不要求用户先分类，不为每条素材新建文件；只在写入并回读成功后简短告知记了什么。接口不可用时如实说明未写入，不绕过保护直接改文件。
3. 用户要求批次整理后，由 AI 读取材料、搜索已有主题、去重并补入对应章节；保留来源和独特内容，区分外部说法、个人理解、待验证与待学习，不把 AI 整理完写成用户已学会。
4. 写前 read / show_diff，写后回读并 validate；处理后保留去向和来源索引。不自动定期处理、删除原材料或发布；暂不适合入书的留在收集入口。

### 从当前对话提炼待学问题

适用于开发、调研或日常讨论后，用户想知道“哪些点我其实还没懂”。

1. 读取 references/development-conversation.md。
2. 只保留会改变以后判断、排查顺序、技术选择或表达能力的主题。
3. 先列 1–8 个候选给用户选择；不要为了凑数量拆主题。
4. 用户确认要记录后，进入“记录待学问题”路线。

### 训练、检验与学习路径

适用于“教我”“考考我”“五分钟讲一下”“我是不是掌握了”。

1. 读取 references/training-and-assessment.md。
2. 先让用户自己输出，再根据真实回答指出知识、结构和表达问题。
3. 不编造答题结果、卡点或长期进步。
4. 真正学完后，只有确认过的理解和反复盲点才进入知识库。

### 记录待学问题

适用于“记一下”“以后学”“我这个不懂”。

1. 读取 references/capture-topic.md。
2. 先 search，避免把已有主题重复写进待学清单。
3. 通过 knowledge-mcp 受保护写入，增量追加到现有「学习-需要学习的」文档；按当前库规则定位路径。一般素材暂存走上面的收集路线。
4. 不为每个待学点新建草稿文件。

### 整理调研

适用于一个主题需要保留来源、实测、选型依据，但还不适合成为长期文章。

1. 先 search 是否已有同主题调研或主文章。
2. 按当前库规则补入既有同主题调研或辅助材料，不按每次搜索新建文件。
3. 结论如果稳定、以后会复用，提炼回对应顶层主文章；调研本身默认不加 阅读/沉淀。
4. 快速变化内容保留日期、来源和验证边界。

### 沉淀正式知识

适用于“整理成文章”“写进知识库”“把这次学到的长期留下”。

1. 读取 references/writing-record.md。
2. search 已有主题，再 read 原文和相关来源。
3. 只写已经确认的理解、真实案例和真实卡点；AI 猜测保留为待验证，不升级成事实。
4. 用 show_diff 预览，再 apply_change；新主题才 create_document。
5. 写后 read 回读并 validate。
6. 只有“半年后本人仍值得主动重读”的成品文章才加 阅读/沉淀。

### Obsidian 与库维护

适用于 Obsidian、本地 Markdown、Canvas、Bases、双链或目录维护。

1. 读取 references/vault-ops.md。
2. Obsidian 只是本地查看/编辑工具，不是第二真源。
3. 库结构、元数据和完整性以 knowledge-mcp 当前 README / docs / validate 结果为准。
4. 保留当前单一待整理入口，不恢复旧生成阅读层、平行草稿箱或概念卡体系。

## 共通边界

- 公司资料进入 company scope，不复制到 personal；只有脱敏后的通用知识才能进入个人主文章。
- 外部资料先区分“原文事实 / 自己理解 / 待验证判断”，不要把第三方说法写成自己的确认结论。
- 快速变化领域写入长期知识前优先核对官方或一手来源，并留下时间边界。
- 学习过程可以保留在对话或既有历史学习稿中；新的长期知识默认不要再复制成“主文章 + 概念卡 + wiki + 草稿”四份。
- 对知识库的写操作遵守 knowledge-mcp 自己的 WRITE_SAFETY；不绕过受保护写入。
