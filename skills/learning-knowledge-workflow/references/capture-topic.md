# 记录待学问题

“以后学”“这个我不懂”记录为待学问题，不为每个问题创建草稿文件。用户只是要先存链接、截图或想法时，走 SKILL.md 的素材收集路线，不强行提炼成学习待办。

## 唯一入口

统一追加到 knowledge-mcp 的：

现有「学习-需要学习的」文档。先按当前库规则核对路径；目前位于 `personal/辅助材料/学习-需要学习的.md`。

写入前先 search 当前主题；如果已有正式主文章而且用户只是要补一个缺口，优先把“待补的问题”记在该主题上下文里，不重复制造待办。

## 每条至少保留什么

按日期追加，保留最小信息：

- **问题**：具体哪里没懂，不写成空泛关键词；
- **为什么值得学**：学会后会改变什么判断、定位或行动；
- **来源**：本次对话 / 真实项目 / 书 / 文章 / URL；
- **真实场景**：只有真实发生过才写，没有就明确没有；
- **待验证**：还不能确定的部分。

如果用户已经明确说了自己的初始判断，可以保留原意；没有就不要替他补。

## 价值门槛

满足至少一条才记录：

- 后续主题的前置知识；
- 纠正了真实误解；
- 会改变技术选择、排查顺序或产品判断；
- 在真实任务里反复出现；
- 能连接两段原本不理解的调用链；
- 同类盲点复现；
- 以后很可能再次遇到。

“AI 随时能重新解释的一句定义”通常不需要进入待学清单。

## 写入方式

使用 knowledge-mcp 的 search / read / show_diff / apply_change，写后回读并 validate；不要直接手改文件，不要创建 草稿-YYYY-MM-DD-xxx.md，也不要在现有待整理入口之外再建一套草稿箱。
