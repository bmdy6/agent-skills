# 正式学习与知识沉淀

目标不是把一次对话保存下来，而是让以后重新打开时能快速恢复自己的理解。

## 写之前

1. search 当前主题，确认有没有主文章。
2. 有主文章就 read 原文；不要因为这次来源不同就新建第二篇。
3. 需要历史证据时再读旧学习稿、调研或旧库来源。
4. 区分四类内容：
   - 已验证事实；
   - 用户已经形成的理解；
   - 用户真实暴露的卡点；
   - 还没验证的推测。

最后一类不能写成确定结论。

## 学习过程怎么处理

学习时可以继续用寓言、类比、检验题、反向教学和真实代码实战，但这些是**训练手段**，不是强制的知识库文件结构。

- 寓言只在确实能降低理解门槛时用，不为了模板每篇都写。
- 检验问题必须等用户真实回答，AI 不能预先编造“你可能会卡住的地方”。
- 用户主动提出的困惑也算真实学习证据。
- 语音场景先区分 ASR 转写错误和用户真正的表达/知识错误。
- 新学习默认不再创建“主文章 + 概念卡 + wiki + 草稿”多份副本。

## 主文章怎么写

主文章负责当前最稳定、最值得二次阅读的理解。

优先结构：

1. 一句话核心认知；
2. 这个问题为什么存在；
3. 最关键的机制或边界；
4. 一个真实或足够具体的例子；
5. 常见误解 / 自己真实踩过的坑；
6. 什么时候用、什么时候不用；
7. “半年后只看这里”式的简短回顾（主题较复杂时再加）。

不机械追求固定章节数量。文章要让本人半年后重新看得下去，不写成课程讲义或 AI 百科。

## 真实卡点怎么留下

只有用户真的答错、追问或在项目中判断错，才记录。

可用这种最小格式：

### YYYY-MM-DD｜一个真实卡点

- 我当时怎么理解：
- 哪一步不对：
- 现在怎么判断：
- 以后看到什么信号要想起它：

如果主文章已经很成熟，卡点可以只吸收成“常见误解/边界”，不必保留整段对话。

## 调研和正文的关系

原始调研、比较表、时效性数据放 personal/调研/<主题>.md。

长期主文章只吸收经过判断后仍然成立的结论，并在必要时保留来源或时间边界。不要把整篇调研复制进正文。

## 阅读/沉淀

只有满足这些条件时才给文章加 阅读/沉淀：

- 半年后本人仍可能主动打开；
- 不依赖当前一次任务才能理解；
- 已经把过程噪音去掉；
- 能快速恢复核心认知；
- 没有明显未核实的关键结论。

这个 tag 只表示“允许进入 Workbench 精选阅读层”，不表示内容永远不会再改。

## 写入安全

- 先 show_diff，再 apply_change；新主题才 create_document。
- 写完 read 回读并 validate。
- 同一主题优先增量更新，不创建版本号文章。
- 快速变化的模型、框架、政策、价格等内容写日期和适用边界。
- 不把公司内部信息复制进 personal。
